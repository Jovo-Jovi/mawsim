### Notes for the reviewer
- Not-found mechanism: the segment `not-found` inside the locale layout, not `global-not-found`. `/not-a-page` matches `[locale]`, so a global file would not serve it. Calling `notFound()` before the layout returns `<html>` makes Next recover the response as `<html id="__next_error__">`, and the probe then reads empty `lang` and `dir`. The layout (unknown segment) and the catch-all (known locale, unknown rest) therefore render `not-found.tsx` first and call `notFound()` from a child inside `<Suspense>`. The status stays 404, the html tag keeps `lang` and `dir`, and the localized main stays in the HTML. The catch-all module itself does not read params; `not-found.tsx` reads the locale through `next/root-params`.
- `src/i18n/root-params.d.ts` declares `locale(): Promise<string>` because `next/root-params` is an empty module until `next build` writes `.next/types/root-params.d.ts`, and typecheck runs before that build. The named import is the call Next treats as the root param. A cast through `import * as` postponed the param and left the html tag out of the 404 document.
- The next-config tests assert the literal redirect, the absent rewrite, and the absent header conditions because the fence requires those literals.
- No dependency was added. No middleware, proxy, second redirect, rewrite, cookie, form, header read, or `"use cache"`.
