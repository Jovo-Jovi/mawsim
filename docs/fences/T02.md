### Prompt

This task adds **one** thing: the security headers baseline of `docs/SECURITY_MODEL.md` §4 on every route, with a
Vitest test that proves each value. It builds no page, no route, no middleware. Automated profile (PR-01).

**Preconditions — HALT if any is false.** `node scripts/devos/fence-check.mjs docs/fences/T02.md` prints OK.
`next.config.ts` exists with `cacheComponents: true` (on a first attempt it has no `headers` key; on a later attempt
the previous attempt's work is in the tree, so `headers` and `poweredByHeader` may exist and are verified, not
repeated). `find src -name route.ts` prints only
`src/app/api/health/route.ts`. No `middleware.ts` or `proxy.ts` exists at the root or in `src/`.

1. **Headers on every route.** In `next.config.ts`, add an async `headers()` returning one rule with
   `source: "/:path*"` (it matches `/`, every page, `/api/health` and the not-found answer) carrying exactly these six
   headers, names and values character for character:

   | Header | Value |
   |---|---|
   | `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'` |
   | `Strict-Transport-Security` | `max-age=86400` |
   | `X-Content-Type-Options` | `nosniff` |
   | `Referrer-Policy` | `strict-origin-when-cross-origin` |
   | `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), browsing-topics=()` |
   | `X-Frame-Options` | `DENY` |

2. **Development only.** `script-src` gains `'unsafe-eval'` (giving `script-src 'self' 'unsafe-inline'
   'unsafe-eval'`) **only** when `process.env.NODE_ENV === "development"`. Every other value — `production`, `test`,
   unset — gets the production CSP above (fail closed). Read `NODE_ENV` when `headers()` runs, not at module load, so
   one import of the config can be tested in both modes. Keep the CSP's directives in one place in the file (no copy of
   the string for each mode): `'unsafe-eval'` appears on exactly one line of `next.config.ts` (a single conditional
   entry), and no comment in the file contains `includeSubDomains`, `preload`, `nonce`, `unsafe-eval` or a URL.
3. **No `X-Powered-By`.** Set `poweredByHeader: false`. Keep `cacheComponents` and `partialPrefetching` as they are.
4. **The test.** Create `tests/security-headers.test.ts`. It imports the default export of `../next.config` (no
   `.ts` extension: `tsconfig.json` has no `allowImportingTsExtensions`), narrows the optional `headers` and calls it;
   use `vi.stubEnv` for `NODE_ENV` and `vi.unstubAllEnvs()` after each test. It has exactly **seven** `it`s, one per
   bullet below except the fifth, which is two (`test` and unset), each named for the break it catches:
   - with `NODE_ENV=production`: exactly one rule, `source` `/:path*`, exactly the six header names of step 1 (no
     extra, none missing) and each value equal to the table's string;
   - the production CSP contains no `'unsafe-eval'`, no `http:`, `https:`, `*` or other host source, and has
     `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'none'`;
   - `Strict-Transport-Security` does not contain `includeSubDomains` or `preload`;
   - with `NODE_ENV=development`: the CSP equals the production CSP with `'unsafe-eval'` added to `script-src` and
     nothing else changed; the other five headers equal production's;
   - with `NODE_ENV=test` and with `NODE_ENV` unset: the CSP equals the production CSP;
   - `poweredByHeader` is `false`, and `cacheComponents` is still `true`.
   Use exact string comparison against values written in the test, never against values imported from the config
   (a test that reads the expected value from the code under test catches nothing).
5. **Prove it on the built app.** After `pnpm run build`, run the probe (it starts and stops its own server; never
   stop a process by name, PR-71) on `/api/health`, `/` and an unknown path, and paste its output.

**STOP block.**
- **HALT** (report and stop): a precondition is false; a header value cannot be set exactly as §4 states; a check
  cannot pass without changing a file outside Paths (`src/**`, `package.json`, `docs/**` other than the report,
  `scripts/**`, `devos/**`, `content/**`); meeting a step would need a nonce, middleware, a proxy, a dependency, a
  third-party origin or `includeSubDomains`; the build or the probe shows a header missing on any of the three paths.
- **REDACT-AND-CONTINUE**: a log or pasted output that shows a local path, token or machine name is cleaned before it
  lands in the report; the work continues.
