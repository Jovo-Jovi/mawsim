1. **Domain types and season logic.** Create `src/domain/season.ts`. It is pure TypeScript and imports nothing outside
   `src/domain`. It exports:
   - `produceKinds`, the tuple `["fruit", "vegetable", "leafy"]` (`as const`), and `type ProduceKind` derived from it;
   - `type CalendarMonth`, the union of the literals 1 to 12; `calendarMonths`, the twelve values in order; and
     `type SeasonMonths = readonly CalendarMonth[]`;
   - `isCalendarMonth(value: unknown): value is CalendarMonth`, which is true only for the integers 1 to 12;
   - `isInSeason(months: SeasonMonths, month: CalendarMonth): boolean`;
   - `cairoMonth(date: Date): CalendarMonth`. It reads the month of `date` in `Africa/Cairo` through
     `new Intl.DateTimeFormat("en-US", { timeZone: "Africa/Cairo", month: "numeric" })`, taking the `month` part of
     `formatToParts`. The locale is pinned, so the host's language or calendar cannot change the digits. It checks the
     number with `isCalendarMonth` and throws a fixed `Error` otherwise. It never uses `getMonth()` or `getUTCMonth()`;
   - `filterByKind<T extends { kind: ProduceKind }>(rows: readonly T[], kind: ProduceKind | null): T[]`. A `null` kind
     means every kind. Both cases keep the input order;
   - `parseMonthParam(value: string | string[] | undefined, fallback: CalendarMonth): CalendarMonth`. It accepts only a
     single string that is exactly one of `1`…`12` in ASCII digits, with no sign, space, leading zero or decimal point.
     Anything else, an array included, returns `fallback`;
   - `parseKindParam(value: string | string[] | undefined): ProduceKind | null`. It accepts only an exact,
     case-sensitive member of `produceKinds`. Anything else returns `null`.

   `src/domain/index.ts` keeps its rule comment and re-exports all of `./season`.
2. **The catalogue.** In `src/modules/produce/`:
   - `catalogue.ts` is the only non-test file in `src/` that names `content/produce.json` (it imports it by a relative
     path). It exports `interface Produce` with exactly the seven fields of `CONTENT_MODEL.md` §1 and their names
     (`slug`, `en`, `ar`, `kind: ProduceKind`, `months: SeasonMonths`, `tip_en`, `tip_ar`), all `readonly`. It also
     exports `parseProduceRows(raw: unknown): readonly Produce[]`, which checks every rule of §1, including each
     field's type, and returns the rows in file order. Each row is built from the seven fields, and an extra key is
     never copied. A broken input throws `Error` with a fixed message that names the 0-based row index and the rule,
     for example `produce row 3: months must be unique integers 1-12`; input that is not an array gets
     `produce rows: not an array`. The message never contains a field's value. The module
     parses the file once, at load, through this function. No type assertion (`as Produce`, `as ProduceKind`,
     `<Produce>`) types the JSON; `as const` elsewhere is allowed.
   - `listProduce(): readonly Produce[]` returns all rows in file order. `getProduceBySlug(slug: string): Produce |
     undefined` matches exactly: no trimming, no lowercasing, no decoding. `inSeasonIn(month: CalendarMonth): readonly
     Produce[]` returns the rows in season that month, in file order (through `isInSeason`).
   - `this-month.ts` exports `async function thisCalendarMonth(): Promise<CalendarMonth>`. Its first statement is
     `"use cache"`, then `cacheLife("hours")` from `next/cache` (D-02, `STACK.md` §4). It returns
     `cairoMonth(new Date())`. Outside test files, this is the only `new Date()` in `src/domain` and `src/modules`, and
     the only `"use cache"` in `src`. No comment repeats either text.
   - `index.ts`, the public entry, exports the type `Produce`, re-exports the types `ProduceKind`, `CalendarMonth` and
     `SeasonMonths`, and exports `listProduce`, `getProduceBySlug`, `inSeasonIn` and `thisCalendarMonth`. Nothing else.
