### Stage 2 — The generator script (proves D6–D11; the last stage runs every Done-when command)

Files: `scripts/images/generate.mjs`, `tests/images/generate.test.ts`, `docs/STACK.md`.

6. **`scripts/images/generate.mjs`** (plain ESM, Node 22, no dependency). It exports pure, testable functions and runs
   `main()` only when it is the entry file (`import.meta.url` equals `pathToFileURL(process.argv[1]).href`).
   - **Slots**: `hero`, `texture`, then each produce in `content/produce.json` order (12 slots). They save to
     `public/photos/hero/hero.<ext>`, `public/photos/texture/texture.<ext>` and `public/photos/produce/<slug>.<ext>`.
     The aspect ratios are `1:1`, `1:1` and `4:3` (`DESIGN_SYSTEM.md` §11).
   - **Prompts**, one per slot, built from the produce's English name and kind with the art direction of §11: one
     fresh produce or a small group, warm natural daylight from one side, soft shadows, three-quarter view from
     slightly above, centred with a margin, a natural photograph with real texture, no text, logos, hands or people,
     no glossy or plastic look. The surface is linen for fruit, wood for vegetable and a market crate for leafy. Write
     a hero prompt (a wider market composition of several produce on a crate) and a texture prompt (a flat, even,
     overhead close-up of linen weave with no produce and no strong shadow). Keep the prompt templates in one exported
     constant, so the owner can tune them.
   - **Alt text**, built from the produce's own `en` and `ar` names: produce `Fresh {en} on {surface}` and
     `{ar} على {surface_ar}`, where the surfaces are linen/قماش الكتان, wood/سطح خشبي and a market crate/صندوق في
     السوق; hero `Egyptian fruit and vegetables on a market crate in warm daylight` and
     `فواكه وخضراوات مصرية على صندوق في السوق في ضوء نهار دافئ`; texture `Linen texture` and `نسيج من الكتان`.
   - **Request**: `POST https://api.x.ai/v1/images/generations` with the headers `Authorization: Bearer <key>` and
     `Content-Type: application/json`. The body is `{ model: "grok-imagine-image-2.0", prompt, n: 1, resolution: "2k",
     aspect_ratio, response_format: "b64_json" }`. The image is `data[0].b64_json`. A non-2xx answer throws
     `xai: request failed with status <code>`, and an answer without an image throws `xai: no image in the answer`.
     Neither message includes the key or the response body. `fetch` is injected, so tests pass a mock.
   - **Size and format**: an exported `readImageSize(buffer)` returns `{ format, width, height }` for PNG (IHDR),
     JPEG (the first SOF0–SOF3 marker) and WebP (VP8, VP8L, VP8X), and throws `image: unknown format` otherwise. The
     extension follows the format (`.png`, `.jpg`, `.webp`).
   - **Manifest upsert**: it reads `content/photos.json` and replaces the row with the same key in place, or appends a
     new one. The row has `source: "generated"`, the model id, the prompt, `generated_on` (today's date, with `now`
     injected), `terms_url: "https://x.ai/legal/terms-of-service"`, the alt text, the measured `width` and `height`,
     and `credit_required: true`. The file is written with two-space JSON and a final newline. An old file of the same
     key with another extension is left in place and named in the output as unused.
   - **CLI**: `node scripts/images/generate.mjs [--only <key>[,<key>…]] [--dry-run] [--root <dir>]`. `--root`
     defaults to the current folder. The arguments and every `--only` key are checked first, before anything is
     printed or called; errors go to standard error. `--dry-run` prints one line per slot (`<key> <aspect_ratio> <prompt>`), needs no
     key, calls nothing and writes nothing. Otherwise, without `XAI_API_KEY` it prints `XAI_API_KEY is not set` and
     exits 1. An unknown `--only` key exits 1 with `unknown slot: <key>`. It never prints, logs or writes the key, and
     it creates no `.env` file. It works through the slots one at a time and prints one line per saved file.
7. **Tests**, in `tests/images/generate.test.ts`, with a mocked `fetch`, a fake key `test-key-not-real`, a fixed
   `now`, and a root made with `mkdtempSync` in the OS temp folder (copy `content/produce.json` and an `[]`

   - the 12 slots, in order, with their aspect ratios;
   - each prompt contains its produce's English name and "no text", and the texture prompt contains no produce name;
   - the request's URL, method, headers and body, field by field;
   - a run writes the file under the temp root, and its row passes the **real** `parsePhotoRows` from

   - a non-2xx answer and an empty answer throw their exact messages;
   - `readImageSize` handles small handmade PNG, JPEG and WebP headers, and refuses unknown bytes;
   - the key never appears in any thrown message or console output (spy on `console`);
   - `--dry-run` writes nothing.
