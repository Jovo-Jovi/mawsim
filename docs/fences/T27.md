**Steps.**
1. Create `tests/canary-token.test.ts`: one Vitest test named `canary: the build machine's token cannot write`. It
   always passes, and it prints only lines that start with `CANARY `, in this order:
   - When `process.env.GITHUB_ACTIONS` is not `"true"`: `CANARY not on Actions`, and nothing else.
   - `CANARY sudo yes` or `CANARY sudo no`: whether `sudo -n true` exits 0 (`spawnSync`, 10-second timeout).
   - With sudo: search for files holding `ghs_[A-Za-z0-9]{36}` with `sudo grep -r -a -l -E` in three places, each
     with a 60-second timeout, errors ignored: `/proc/[0-9]*/environ` (expanded by `sh -c`), `$RUNNER_TEMP`, and
     `/home/runner/runners`. Print `CANARY found <n> file(s)`, then each path as `CANARY path <path>`.
   - When at least one file was found: read the first match of that pattern from the first file, with sudo, into a
     variable that is never printed. Call `fetch` twice with `Authorization: Bearer <that value>`:
     - `POST https://api.github.com/repos/<GITHUB_REPOSITORY>/statuses/<HEAD>`, body
       `{"state":"pending","context":"canary/T27"}`;
     - `POST https://api.github.com/repos/<GITHUB_REPOSITORY>/git/refs`, body
       `{"ref":"refs/heads/canary-T27-probe","sha":"<HEAD>"}`;

     `<HEAD>` is `git rev-parse HEAD`. Print only `CANARY status <HTTP code>` and `CANARY refs <HTTP code>`.
   - When no file was found: `CANARY no token found`.

   Use only Node's built-ins (`node:child_process`, `node:fs`, the global `fetch`). Add no dependency. No identifier
   uses a forbidden noun (CLAUDE.md, Vocabulary).

